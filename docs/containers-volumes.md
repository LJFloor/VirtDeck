# Containers: volumes

The third tab: `docker volume ls` with the stack, driver and creation time, plus creating one, removing one, pruning the unused, measuring one, moving one to and from this PC as a tar of its files, cloning one, and opening its directory in the File explorer. `Views/DockerVolumeRow`, `Views/Containers/{VolumeCreateDialog,VolumeImportDialog,VolumeCloneDialog}`, `Core/Models/DockerVolumeInfo`, `Core/Services/BrowseRequests`, and the Volumes half of `Core/Services/DockerService`.

- **The listing is one round trip with four tags**, in `NetworksScript`'s shape: `v` a volume, `p` its creation time, driver option count and mountpoint (a batched `docker volume inspect`, since `volume ls` reports none of them), `k` that `docker ps` could be asked, and `u` one container, whether it runs, and every volume it mounts (a batched `docker inspect`). `{{len .Options}}` answers 0 for a volume whose `Options` is null, which is every plain local one. No cap on the split: a volume name is `[a-zA-Z0-9][a-zA-Z0-9_.-]+` and the mountpoint, last, is a path docker built.
- **Rows merge on the name**, because docker has no id for a volume. An anonymous volume (64 hex) is drawn cut to 12 characters, dimmed whole the way a dangling layer is, and sorted last.
- **One usage count, not the networks table's two.** `docker volume rm` refuses, and `docker volume prune` spares, a volume any container mounts, stopped ones included (measured on docker 29.1.3: rm refused a volume only a created, never started container mounted, with `-f` as without it). So Status counts every container, the tooltip names them and marks the stopped ones, and amber **Unused** is again what Prune's all-unused answer takes. Blank without `k`, the Images table's third state.
- **Created is rendered and read back.** Docker prints RFC3339, which stops sorting as text once two volumes carry different offsets, so the row parses it into an instant for the sort, draws local `yyyy-MM-dd HH:mm`, and keeps docker's string as the tooltip.
- **No force path on Remove**, because `-f` does not override "volume is in use". Remove skips the volumes the listing knows are mounted (the bulk rule) and the confirmation says so; whatever docker still refuses is reported in its own words.
- **Prune is two answers where docker has two.** Since docker 23 a plain `docker volume prune` takes only anonymous volumes and `--all` takes named ones too, so it is `Choose` with **Remove anonymous only** as the primary. Before 23 plain prune took named volumes and `--all` did not exist, so `PruneDistinguishesAnonymous`, read off the client version, turns it into one `Confirm` that says named volumes go too. The report is docker's own.
- **Everything that touches the files works on the mountpoint, on the host, as root**, not through a helper container: no image has to be present or pulled, and nothing depends on a registry. The price is that it means something only for a plain `local` volume, so Browse files, Measure size, Export and Clone are disabled for another driver and for a local volume with driver options. That second kind is a mount (NFS, CIFS, tmpfs) docker performs only while a container uses it; its directory is empty the rest of the time and an archive of it would be an empty success. `DockerVolumeRow.HostPathReason` is the reason, on the disabled menu items through `ToolTip.ShowOnDisabled`. Each script re-resolves the mountpoint at run time and tests that it is a directory rather than trusting a listing a cycle old.
- **Size is on demand and never part of the listing.** A measurement is `du -sb` and walks every file, so it is a right-click, streamed on its own connection rather than through `RunSudoCommand` (whose lock would stand every other module still for as long as a media volume takes to walk), and it fills rows in as each volume finishes. Readings are held on the module the way the CPU sample is, for the same reason, and cleared when the tab is left: a volume a database writes to is a different size a minute later.
- **Export is a tar of the files, through the image export's picker and `.part` rename** (`PickExportTargetAsync` and `FinishExportAsync`, shared by both). `--numeric-owner`, because the files belong to whatever uid the container runs as, and a restore on another host must put back the number. `set -o pipefail` for the image export's reason. Tar's exit status 1 ("file changed as we read it") is taken as success, and only that one, because it is exactly what copying a volume in use produces and the user was asked about that first.
- **A running container is a question every time.** Before Export and Clone the listing is read again, and any running container that mounts the volume is named in a `Choose`. **Export while running** is the primary, because Enter must not stop somebody's service; **Stop, export, start again** is the alternative. What was stopped is started again whatever happened, a failure and a cancel included, and a container that will not stop means nothing is copied.
- **Import always makes a new volume**, so there is nothing to overwrite or merge with, and it asks what to call it, suggested from the archive's file name until somebody types (see "Auto-fill"). Both sources, like the image import. For an upload the compression is read off the extension, because GNU tar refuses gzip on stdin without `-z` ("Archive is compressed. Use -z option", measured on tar 1.35); a file on the host is sniffed by tar itself.
- **An import or a clone that fails or is cancelled removes the volume it created.** Nothing else can be using it yet, and a half-restored volume under the chosen name would read as a finished one.
- **Clone is `cp -a`** into a new plain local volume. Labels are not copied, so a compose project does not claim the copy as its own.
- **Browse files hands the mountpoint to the File explorer** through `BrowseRequests`, a per-connection slot in `PackageService.For`'s shape, plus `IModuleNavigator`; the explorer takes it in its own activation and pre-approves it for root (see "Listing as root").
- **Dropping a `.tar`, `.tar.gz` or `.tgz` on the tab opens the import dialog** with the file filled in, because dropping a file is not naming the volume.
- **No Refresh button.** The event tail carries `type=volume` (a volume speaks `create`, `destroy` and `prune`, and a prune also emits a `destroy` per volume), and a container event refreshes this table when it is on screen, because creating or removing a container is what moves Status.
- **Not here yet:** a size column that fills itself, restoring into an existing volume, cloning onto another driver, and anything that reads the files of a plugin or share volume.
