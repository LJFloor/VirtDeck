# Containers: networks

The third tab: `docker network ls` with the driver, scope, subnet and gateway, plus creating one, removing one, pruning the unused, and attaching or detaching a container. `Views/DockerNetworkRow`, `Views/Containers/{NetworkCreateDialog,NetworkAttachDialog}`, `Core/Models/DockerNetworkInfo`, and the Networks half of `Core/Services/DockerService`.

- **`DockerNetworkInfo` and `DockerNetworkRow` carry the prefix because `NetworkInfo` and `NetworkRow` were taken**, in the very same namespaces, by the **libvirt** networks the VM module lists. The two subjects have nothing to do with each other and the names had to say so.
- **The listing is one round trip with four tags**, in `ImagesScript`'s shape: `n` a network, `p` its live endpoint count and IPAM, `u` one container and the networks it is configured on, `k` that `docker ps` could be asked at all. `docker network ls` reports neither subnet nor gateway, so the `p` half is a batched `docker network inspect`, never one per row. `[ -n "$ids" ]` guarding that batch is load-bearing rather than tidy: neither GNU nor busybox `xargs` implies `-r`, so a host with no networks would otherwise run `inspect` with no arguments. Splitting needs no cap, because a network name, a container name and a driver are all `[a-zA-Z0-9][a-zA-Z0-9_.-]*`; a `p` record for `host` or `none` simply ends in two empty fields, which is an ordinary answer and not a missing one.
- **The Status column counts live endpoints, and the tooltip counts configured containers, and the difference is the whole point.** `docker network prune` and `docker network rm` key on live endpoints; stopping a container tears its endpoint down. So a network two **stopped** containers are configured on has none, and Prune takes it (measured: created a network, ran two containers on it, stopped both, `{{len .Containers}}` went to 0 while `docker ps --all`'s `{{.Networks}}` still named it twice, and `docker network prune` deleted it; the container then failed to start with "network ... not found"). Drawing "2 containers" there would put a reassuring number on a row Prune removes anyway, so the amber is read off the endpoint count and the column keeps the Images table's invariant exactly: **amber "Unused" means what Prune would take**. What the configured containers buy instead is the Status **tooltip**, which is the one place the part Prune does not say gets said: how many stopped containers still name it and that they will not start once it is gone. Both halves ride the same round trip, so the honest reading costs nothing.
- **A predefined network never wears the amber**, however empty it is, because `docker network prune` skips `bridge`, `host` and `none` by name. It reads a plain "No containers". That is also why `IsPredefined` keys on the **name** rather than the id: docker's own check does.
- **The `k` tag gates the member list, not the column.** Because Status comes off the `p` half, usage is known per network (it has a `p` record or it does not), which survives `xargs` splitting the batch and one invocation failing. What `k` answers is whether `docker ps` could be asked at all, and so whether `Members` is empty because nothing is attached or because nobody could look; Connect and Disconnect are disabled without it, rather than opening a picker whose emptiness reads as "nothing to disconnect".
- **There is no state dot and no row dimming.** A container is doing something, a network is a fact, which is the Images tab's reason; and unlike a dangling layer, no network is a leftover.
- **There is no force path on `rm`, and that is not an omission.** `-f` on `docker network rm` means only "do not error if it does not exist", so a network with live endpoints is a refusal docker owns and it is reported in docker's own words, the way `groupdel`'s is in User accounts. There is no `NeedsForce` twin. `docker network rm` does need one piece of tidying the other network commands do not: it writes the daemon's message **and** a bare `exit status 1` line, both to stderr (measured; no other one does), and `RunSudoCommand` merges stderr in, so a refusal would otherwise read "...has active endpoints / exit status 1".
- **Remove skips docker's predefined three rather than greying out over them.** Everywhere else an unavailable command states its reason on hover, but a `ContextMenu` item has no enabled parent `Border` to hang a tooltip off and a disabled control is not hit-testable, which is why no item in this module's menus carries one. So Remove takes the module's bulk rule instead, enabled when at least one selected network can go and running only on those, and the **confirmation** says the predefined ones are left alone.
- **Prune asks with `Confirm`, not `Choose`**, because unlike `docker image prune` there is no `--all` second degree to offer. It reports what docker itself said it deleted rather than predicting it, exactly as the images prune does.
- **Connect and disconnect exist because nothing else can do them.** `docker create` fixes a container's networks and `docker update` does not reach them, so the edit window's Network page can only ever answer the question at creation. `docker network disconnect` works on a **stopped** container, which is why that picker lists what is configured rather than what is running: a container that will not start for want of a network is exactly the case somebody is here to fix. `--force` on disconnect is not offered, because it is for a container the daemon cannot reach and this table cannot tell anybody they are in that state.
- **`--ip` is offered on a user-defined network only**, which is docker's own rule ("user specified IP address is supported on user defined networks only"), and the predicate is `!IsPredefined` rather than "has a subnet": a user-defined bridge always gets one from the default pool, so gating on the subnet would grey the box on exactly the networks where it works. In disconnect mode the row is **hidden** rather than disabled, because there the field does not apply to the operation at all, which is the Network page's own rule for the port mappings on `host` and `none`.
- **The create dialog's driver box is an `AutoCompleteBox`**, for the reason the container editor's image field is: it has to suggest what the host has and still accept a plugin driver on no list. Seeded from `docker info --format '{{.Plugins.Network}}'`, which prints a Go slice, probed once per session and falling back to the built-ins, the same "union the built-ins in rather than trust the listing to arrive" move `FetchCatalog` makes. `host` and `null` are dropped from the suggestions because docker predefines one of each and refuses a second. Gateway and IP range are **disabled with their reason on hover until a subnet is typed**, because docker refuses them without one.
- **Every command addresses a network by id and rides `ShellScript.Argv` behind a literal `--`.** Create is the one that takes user text, and it takes the same route, so there is no special case and no `RequireId` twin.
- **No Refresh button**, because the tail now carries network events; and a **container** event refreshes this table when it is the one on screen, since starting or stopping a container is the only thing that moves the Status column.
