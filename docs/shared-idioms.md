# Shared idioms

These recur across most of the app. A section below only spells out where it *deviates*.

**Tab walks.** `ShellView` (`IModule`), `UnattendWindow` (`IUnattendTab`) and `ContainerEditWindow` (`IContainerTab`) all walk their `TabControl`'s items and call the interface on whichever contents implement it, so the host **never names its pages** and adding one is a `TabItem` plus a `UserControl`. Two invariants follow: every page is constructed with its window (they are literal elements, not template output), so a page the user never opened must still behave; and pages own disjoint state, so `Apply`/activation order never matters. Where two pages constrain each other, the resolution belongs in the mapper or the argv builder, never in ordering.

**Long calls get their own SSH connection.** `RunCommand`/`RunSudoCommand` hold `_ioLock` for the whole call, so anything that streams or lasts (`RunCommandStreaming`, `RunSudoCommandStreaming`, `RunPipeInAsync`, `RunPipeOutAsync`, `OpenPipeAsync`, `DownloadFileAsync`, `SshPtySession`, every event tail) opens a client of its own. Otherwise one `cp` stalls every other module. Those callers must also spell out their own wrapper: unlike `RunSudoCommand`, the streaming pair neither escapes its argument nor wraps it in `bash -c`.

**One round trip, tagged records.** A listing script emits a tag in field 0, **real tab characters** (never `\t` escapes), exports `LC_ALL=C`, fences every best-effort half with `2>/dev/null` so it cannot take the exit status with it, and ends `exit 0`; only the one command whose failure means the listing failed carries `|| exit $?`. The unbounded field (a file name, a passwd line) goes **last** and the client splits with a cap. Scripts full of braces and quotes are base64'd through `echo <b64> | base64 -d | bash`. A modelled failure is a **value** (`ListFailure`, `PasteBlock`, `UnitCatalog.ListFailure`), not an exception, because the module has to draw it; genuinely unexpected failures still throw.

**User text never reaches the shell by interpolation.** `ShellScript` (`Wrap`, `SudoWrap`, `Argv`, `ArrayFrom`) is the one home for the app's four ways of handing a command to bash; `DockerService.ArgvScript` and `RemoteFileService.Wrap`/`SudoWrap`/`ArrayFrom` forward onto it. An argv is joined **NUL-separated**, base64'd, and rebuilt as a bash array with `read -r -d ''` (not `mapfile -d ''`, so nothing needs bash 4.4). Every vector carries a literal `--` before a user-supplied name. **A password never touches a command line at all**; it goes over stdin (`RunPipeInAsync`).

**A remote command runs in a non-login bash, so the wrappers repair PATH.** SSH's exec channel gives a command sshd's bare default PATH, never the one `/etc/profile` builds for a person who logs in, and nothing in VirtDeck ever set it. `ShellScript.PathExport` is the one answer: it rides in front of `Wrap` and `SudoWrap`'s payloads, beside `RunSudoCommand`'s `export LANG=C` (**inside** the sudo'd bash, so it does not care whether the host's sudoers sets `secure_path`), and in `RunPipeInAsync`'s longhand wrapper. It is **appended**, never prepended, so a host that already has an opinion about which `docker` it wants keeps it and this only adds places to look. Synology DSM named this rule: it hands the exec channel `/usr/bin:/bin:/usr/sbin:/sbin` and installs the docker CLI in `/usr/local/bin`, so `command -v docker` answered nothing and the Containers tab was never drawn on a host running three containers. Only the *wrapped* paths are repaired: the streaming pair passes a bare command, so a caller there spells the export out itself, which `DockerService` does for its three docker streams and no other caller needs.

**Creating versus addressing are different rules.** What VirtDeck will *create* is checked strictly (`IsValidNewUserName` is `^[a-z_][a-z0-9_-]{0,31}$`, what shadow-utils accepts without `--badname`; `SanitizeName` folds to it); what it will *address* (`UserAccountService.RequireSafe`) is checked only for what would be a bug (empty, line break, leading hyphen, wrong suffix), because a name already on the host may be `Debian-snmp` or `systemd-fsck@dev-disk-by\x2duuid-3083\x2dE537.service`. Addressing is safe without a strict rule because of the argv rule above.

**Absent tooling is a stated answer, not an empty list.** `DockerAvailable`, `shadow-utils`, systemd: all default **false**, because the safe default is the one that explains itself. The status slot says so, the table carries a centred message, every command is **disabled with a reason rather than hidden**, nothing polls or tails, and **every re-entry re-probes** while the answer is no, so installing the package mid-session is not a dead end. The KVM probes are the deliberate opposite and default *available*, to avoid a false negative. All of that is about a module that is **on screen**; whether a module appears in the side menu at all is the one page-level exception to the disabled-rather-than-hidden half of it, and is in "Which modules a host gets" below.

**Refresh policy.** A module gets an event tail plus a poll where the host announces changes (`virsh event --loop`, `docker events`, `journalctl --follow`), debounced 400 ms because one action prints several lines; it gets a **Refresh button instead** where nothing announces them (files, accounts). The shell's module probe is a poll for something nothing announces, and it pays for that by being self-limiting: see "Which modules a host gets". The shell's other watcher, for a restart somebody scheduled on the host, is a **tail with the loop on the host**: nothing announces a scheduled shutdown, so a one second loop over `/run/systemd/shutdown/scheduled` prints a line only when the answer moves, which costs one channel and no round trip per tick. That is the shape to reach for wherever a Refresh button has nowhere to go: the host going down is worth knowing about whichever module is on screen. See "Restarting the host". `Deactivate` stops timers and cancels the read in flight so a hidden module costs nothing, but **leaves event tails running**: each holds its own SSH connection and rebuilding one per module switch would cost more than the events are worth. Two tails stop with their page, the containers table's `docker stats` sampler and the network module's traffic tail, and the two halves of that are worth separating: each draws a **value** rather than a history, so the gap costs nothing to come back to, and what it asks of the host is a measurement every few seconds rather than a stream sitting idle until something happens. The Overview module's sampler measures too and is deliberately left running, because there the hole in the graph *is* the cost, and the traffic tail takes the Overview's side for as long as an interface's details window is drawing a graph from it. See "Containers" and "Network". **The logs module's `journalctl --follow` is that argument at full strength, and it is the one tail whose payload is the page rather than a cue to go and read something**: a gap in it is entries nobody will ever see, because nothing will announce them a second time. It runs on through `Deactivate` with the rest. See "Logs". `Shutdown` stops them, because the shell disposes the shared connection (and the auth material every second client borrowed) straight after.

**Rows are merged, never rebuilt.** A poll fires whether or not anybody asked, so a rebuild would drop the selection out from under the pointer. `Views/TableRows` is the one `Merge` + `Reorder`-by-`Move` every table calls, taking each caller's key function, its row factory and its order. Lists merge **by id**, never by name, and the id is not always the obvious field: an image is keyed by id-plus-repository-plus-tag because one image appears once per tag it carries, and a compose project by its name because it has no id at all. `Reorder` keeps a **position index** rather than calling `IndexOf` inside the loop, which on 250 service units is tens of thousands of reference comparisons a pass and a keystroke in a search box runs a whole pass. This was eleven copies that had drifted: the reorder existed three times, once as that quadratic version, and the VM and container tables never called it at all, so a container created after the first listing was appended at the bottom whatever its name was.

**Every table sorts and the long ones filter, and neither ever touches the host.** `Controls/ColumnHeader` is the one heading cell (a flat `JbColumnHeader` button carrying a label and a caret), `Controls/TableSort` is one table's sort state, and `Controls/FilterBox` is the search box with its 150 ms debounce. A header is one line of markup and a module wires one event per table, not one handler and one caret entry per column. Six rules hold across all of them:
- **A header cycles ascending, descending, then back to the table's own order**, caret gone. That third state is what lets the default orders that are argued for elsewhere in this file (running containers first, dangling images last, anonymous volumes last, docker's predefined networks last, ours before discovered stacks, security updates first) survive a table being sorted: they are what the table shows until somebody asks for something else, rather than a grouping that outranks every sort and puts the largest dangling layer down the middle of a table sorted by size. **The file explorer is the exception** and keeps its two-state pair, because directories-first is a file-manager convention rather than a nicety, so there is no natural order for a third click to return to (`TableSort(..., allowDefault: false)`).
- **A column sorts on the value its cell was rendered from, never on the text in it.** "512 MiB" sorts above "4 GiB" as a string, "999MB" above "1.23GB", and "3 weeks ago" does not sort at all. So `VmInfo.MemoryKiB` keeps the number `FormatKiB` was already parsing and throwing away, `ImageInfo.CreatedAt` rides the images listing as one more field, `ImageRow.SizeBytes` reads docker's size phrase back (decimal units, docker's own `HumanSize`), and both uptime columns sort on elapsed seconds. The exception is a string **formatted host-side to sort correctly already**: the file explorer's `Modified`, the images table's `CreatedAt` and the history table's `When` are all fixed-width and ISO-ordered, so lexicographic order already is chronological order and there is nothing to parse.
- **Filtering re-renders the listing in hand.** Every module has a `Populate` between its read and its merge; a keystroke never costs a round trip, the status slot gains **`· filtered`**, and a needle matching nothing draws its own empty text rather than the "nothing here" one, which would be a different and wrong claim. A table whose listing **failed** keeps saying so through both (the containers module holds a failure string per table, the updates module refuses to populate a catalog it could not read, the file explorer latches `_failed`): a sort click must never replace the reason a table is empty with an empty table. **The logs module is the one exception to this bullet, and it is a whole-bullet exception**: its three dropdowns are the query and not a view of an answer already in hand, because the journal is the one host fact too big to read once. Each of them costs a round trip and empties the list, there is no `· filtered`, and what it keeps instead is the rule above: what the host answered is what is drawn. See "Logs".
- **A heading cell may carry no order at all, and the layout does not depend on whether it does.** `ColumnHeader.SortKey` left empty is skipped by `TableSort` rather than cycled into a key nothing answers, The storage module's Filesystem, Mounted at and Used columns were what used that, and they are gone: they described what is stacked on a disk, that table now holds only disks, and the stack moved to the disk details window's partition table, whose headings refuse to sort wholesale rather than three at a time. The **containers table's Ports column** is the one that carries no key today: its cell holds a list of mappings rather than a value, so no ordering of it is about anything, and sorted on its own text it put 1433 above 3306 above 80 above 8002. Such a heading does not merely go unsorted, it stops offering: `TableSort` calls `ColumnHeader.MakeInert` on it, which takes the hover and the click off the cell while leaving its theme, label, padding and inset alone, because a heading that responds to a click by doing nothing is worse than one that does not offer. It stays a `ColumnHeader` and never becomes a `TextBlock`, since `TakeStripInset` reaches only the former and a plain label would lose the inset the strip gives up and hand the edge to its neighbour. `TakeStripInset` therefore runs over **every** heading cell and not only the sortable ones (`TableSort._all` beside `_headers`), because where a cell sits in a strip has nothing to do with whether it has an order; insetting only the keyed ones left the unkeyed ones with no vertical padding while the strip had given its own up, so their hover sat 6px shorter than their neighbours' and the edge inset could go to the wrong cell entirely.
- **Sort and filter are session state on the module**, never in `settings.json`. Switching host builds a new shell, which is what resets them.
- **The strip's inset is inside the cells, not around them** (`TableSort.TakeStripInset`). A heading strip is a `Border` with `Padding="12,3"`, and left there it is padding *around* the cells: the hover stops short of the strip's top, bottom and left edge, so a heading reads as a pill floating in the strip with a dead margin beside it that looks like part of the cell and is not clickable. That is what `HubAccountMenu` says a status bar cell must not be, and a heading cell is the same kind of thing, so the strip gives its padding up, every cell carries the vertical half and the two end cells carry the half they are against. **Nothing moves a pixel**: the leftmost cell is widened by exactly what it took on, so every column after it starts where it did. The strips are `DockPanel`s with the flexible column as the fill child for the same reason, so the last cell is its whole column rather than the width of its label. Which cell is against which edge is read off the panel and not off document order, because among right-docked children the *first* is the furthest right (the file explorer docks from the right, its flexible column being the leftmost one).
- **Every column but the leftmost stands 6px off the column line to its left**, heading and cell alike, so a value does not run up against the end of the one beside it and a heading's hover does not begin exactly where its label does. The row half is the `.cells` style in `App.axaml`, said once for every table rather than on each cell; the heading half is `ColumnHeader.CellInset`. The two have to agree to the pixel or a heading sits off its column. It is a **floor and not an addition**: the leftmost column is against the table's own 12px margin, which already insets it by more, and stacking the two would push that column out of line with the strip above it. The file explorer's row is the one written as a `DockPanel`, and there the direct `TextBlock` children *are* the columns docked from the right, so it needs no `nth-child` rule and would be wrong with one.

A filter box goes only where lists run long: VMs, containers, images, volumes, users, updates, interfaces and the two service scopes. libvirt networks, docker networks, stacks and groups are a handful of rows, and the VM module's Networks page goes on having no toolbar at all rather than growing one to hold a box for three of them. **Ctrl+F** reaches the box of the table on screen (`FilterBox.AttachFindShortcut`, registered on the top level for the reason the file explorer's command keys are), and Escape clears it.

**The client never leads the host.** A tick or a state a command flipped optimistically is put back from the host's answer; a row may say what it has *in flight* (`ServiceRow.Pending`, amber) but never what the host will say. An in-row `CheckBox` is driven by `Click`, not `IsCheckedChanged`, or a poll pushing a value in would generate commands.

**A control disabled for a reason states it on hover.** A disabled control is not hit-testable in Avalonia, so the tooltip hangs off an enabled parent `Border` (`CheckRow`'s template, `MessageDialog`'s alternative button, `ServiceRow`'s autostart tick).

**A window opened over another one is centred on it by hand** (`Services/WindowPlacement`, `ShowCenteredOn`). Avalonia's `CenterOwner` only means anything for a window given an owner, which in practice means a dialog: a long-lived window shown with `Show()` has none, so both `CenterOwner` and `CenterScreen` fall back to centring on the screen the unplaced window claims to be on, the primary one. On a two-monitor desktop that is the wrong monitor every time the shell is not on the primary, and the SPICE console, the disk and pool details windows, a container's logs or console and the host manager all opened across the desktop from the window that asked for them. `Show(owner)` would place them, but it also makes them **transient for the shell**, which pins them above it for as long as they live and closes them with it; these are windows you put where you like and leave behind the shell, so they stay unowned and the placement is done instead: centre on the owner's frame, then clamp inside that screen's work area, because a window centred on an owner near an edge otherwise hangs off the desktop. Best-effort like `ConsoleWindow.KeepOnScreen`, which does the same clamp after a guest resolution change: positioning is a no-op on compositors that do not let a client place its own windows. A **dialog** needs none of this and goes on saying `WindowStartupLocation="CenterOwner"` with `ShowDialog(Owner)`.

**Auto-fill stops when the user types.** `_osUserPicked`, `_nicsTouched`/`_disksTouched`, `DeviceRow.MirrorHostPath`, the user-name and home-directory boxes: a suggestion is written until the box holds something the user typed. Which text is the user's is decided by **comparing the box against the last suggestion written into it**, never by a flag held across the write: Avalonia's `TextBox` raises `TextChanging` inline but **posts** `TextChanged`, so such a flag is already false by the time the handler runs (measured: it froze the user name at `h`). Emptying a box hands it back but does not refill it there and then, since a refill lands a whole name under a caret at its end.

**A caret-preserving fold** (`CreateVmWizard.SanitizeName`, reused by the user-name box) replaces one illegal character with one legal one on every `TextChanged`, restores the caret explicitly, and is reentrancy-safe by being **idempotent** rather than flagged, for the posted-event reason above.

**Icons are decided once per listing.** `FileIcons.Available(size)` decides whether a whole listing gets icons or the fallback badges, so the two never appear mixed; icons are cached by (type, size), **shared by every row so no caller may dispose one**, and warmed inside the same `Task.Run` as the directory fetch so building rows is pure cache hits and an SVG theme never rasterises on the UI thread.

**Reflection into a private is best-effort and fails soft** (`X11KeyboardGrab` digging out Avalonia's display connection, `SshPtySession` reaching `ShellStream._channel` to resize). Never throws, latches its failure so a drag does not retry per frame, and the fallback is a **stated outcome** rather than an improvisation.
